# 2026-10-29

**Changed:**
- `DiskCapGuard` measures the recordings directory on a `grimml-disk` daemon thread instead of inside `StateSampler.sampleAll`
- size uses the walk's `BasicFileAttributes` (one lstat per file)
- `DiskCapSelfCheck` runs in `mvn package` next to the binary format check

**Why:** a spark profile showed `directorySize` at ~97% of the server thread (`lstat`/`stat` over the recordings tree), which spikes MSPT

**Unfinished / next:**
- drop the jar on a test Paper server and confirm the server thread no longer walks the recordings directory
- `MsptGuard` can still unpause a disk-cap pause; see `docs/known-issues.md`

**Watch out for:** the disk thread is joined for 2s on disable and aborts the walk on interrupt. do not call `directorySize` from the main thread
